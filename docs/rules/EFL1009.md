# EFL1009 — Large in-memory `Contains` inside a query

**Category:** Performance · **Severity:** Info · **Code fix:** no

## What

EfLint reports `Contains` over an in-memory collection (array, `List<T>`, `HashSet<T>`,
`IEnumerable<T>`, `ICollection<T>`) used inside a lambda passed to an EF Core query operator
such as `Where`, `Any`, `Count`, `OrderBy` or `Select`.

The rule uses two cases:

- **Known size:** three or more literal values are reported. Two or fewer values are ignored —
  they cannot stress a provider's parameter limit.
- **Unknown size:** an in-memory collection held in a parameter, field or local whose contents
  are not visible at the call site is reported. A caller can pass any number of values, so this
  is the real large-collection case (`int[] ids`, `List<int> ids`, `IEnumerable<int> ids`).

`string.Contains`, `Queryable.Contains` (a SQL subquery), non-EF queries and entity navigation
collections are always ignored.

## Why

EF Core translates `ids.Contains(b.Id)` to a SQL `IN` list. A large list expands into many SQL
parameters (subject to provider limits such as SQL Server's 2100-parameter cap) or, depending on
the EF/provider version, into inlined constants that bloat the plan cache. There is no universal
fix: the right choice depends on the provider, the data and the query. See
[EF Core 8 breaking changes — `Contains` in LINQ queries](https://learn.microsoft.com/en-us/ef/core/what-is-new/ef-core-8.0/breaking-changes#contains-in-linq-queries-may-stop-working-on-older-sql-server-versions)
and [EF Core — improved translation for parameterized collections](https://learn.microsoft.com/en-us/ef/core/what-is-new/ef-core-10.0/whatsnew#improved-translation-for-parameterized-collection).

## Bad

```csharp
var ids = new[] { 1, 2, 3, 4, 5, 6 };
var blogs = db.Blogs.Where(b => ids.Contains(b.Id)).ToList();

var names = new List<string> { "a", "b", "c", "d" };
var count = db.Blogs.Count(b => names.Contains(b.Name));

// Unbounded: the caller decides how many ids are passed.
public IReadOnlyList<Blog> Find(BlogContext db, IEnumerable<int> ids) =>
    db.Blogs.Where(b => ids.Contains(b.Id)).ToList();
```

## Good

```csharp
// Keep the list small when a fixed set is genuinely enough.
var ids = new[] { 1, 2 };
var blogs = db.Blogs.Where(b => ids.Contains(b.Id)).ToList();

// For large sets, push the values into the database instead of parameterizing them:
// a staging/temporary table, a table-valued parameter or a join against the source data.
var result = db.Blogs
    .Join(db.SelectedBlogIds, b => b.Id, id => id.Value, (b, _) => b)
    .ToList();
```
