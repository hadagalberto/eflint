# EFL3001 — Raw SQL built from dynamic values

**Category:** Security · **Severity:** Warning · **Code fix:** yes

## What

`FromSqlRaw`, `ExecuteSqlRaw`, `ExecuteSqlRawAsync` and `SqlQueryRaw` do not parameterize
interpolated values. EfLint reports when their SQL argument is an interpolated string
containing non-constant expressions, a string concatenation with non-constant values,
`string.Concat` or `string.Format`.

## Why

Raw SQL overloads take plain `string`. By the time the string reaches EF Core the values
have already been inlined into the SQL text, so user-controlled input can change the query.
The `FormattableString` overloads (`FromSql`, `ExecuteSql`, `ExecuteSqlAsync`, `SqlQuery`)
keep interpolations as parameters. See
[EF Core documentation — Raw SQL queries](https://learn.microsoft.com/ef/core/querying/raw-sql).

## Bad

```csharp
var posts = context.Posts.FromSqlRaw($"SELECT * FROM Posts WHERE Title = {search}");
context.Database.ExecuteSqlRaw("DELETE FROM Posts WHERE Title = '" + search + "'");
```

## Good

```csharp
var posts = context.Posts.FromSql($"SELECT * FROM Posts WHERE Title = {search}");
context.Database.ExecuteSql($"DELETE FROM Posts WHERE Title = {search}");
```

## Code fix

Replaces the raw method with its `FormattableString` counterpart and converts simple
concatenations into interpolated strings. Calls that pass explicit `object[]` parameters
are reported but not automatically changed, because removing them would alter semantics.

## Configuration

```ini
dotnet_diagnostic.EFL3001.severity = error
eflint.EFL3001.enabled = false
```
