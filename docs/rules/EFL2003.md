# EFL2003 — Non-translatable method inside an EF query

**Category:** Correctness · **Severity:** Warning · **Code fix:** no

## What

EfLint reports calls to user-defined methods inside lambdas passed to LINQ operators
(`Where`, `OrderBy`, `Select`, `Any`, …) on an EF Core query. Methods defined in referenced
assemblies, BCL members such as `string`, `Math` and `DateTime` APIs, `EF.Functions` members and
methods annotated with `[DbFunction]` are not reported.

## Why

The provider must translate the expression tree into SQL. A method it does not know cannot be
translated: depending on configuration the query throws at runtime or silently switches to
client evaluation after materializing every row. See
[EF Core documentation — Client vs. server evaluation](https://learn.microsoft.com/ef/core/querying/client-eval).

## Bad

```csharp
var blogs = db.Blogs.Where(b => IsValid(b)).ToList();

private static bool IsValid(Blog b) => b.Id > 0;
```

## Good

```csharp
// Inline the logic so the provider can translate it:
var blogs = db.Blogs.Where(b => b.Id > 0).ToList();

// Or map the method to a database function:
[DbFunction("IsValid", "dbo")]
private static bool IsValidDb(Blog b) => b.Id > 0;
```

## Configuration

```ini
dotnet_diagnostic.EFL2003.severity = error
eflint.EFL2003.enabled = false
```
