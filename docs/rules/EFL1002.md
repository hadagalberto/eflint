# EFL1002 — Count comparison that can be expressed with Any

**Category:** Performance · **Severity:** Warning · **Code fix:** yes

## What

EfLint reports an EF Core `Count()` call that is only compared against zero or one using
`> 0`, `!= 0`, `>= 1` (or the reversed forms `0 < x`, `1 <= x`). These comparisons answer a single
question — does at least one row exist? — which `Any()` expresses directly.

## Why

`Count()` makes the database run `COUNT(*)` and transfer a scalar back to the client even though
the caller only needs a yes/no answer. `Any()` generates an `EXISTS` query that the database can
short-circuit as soon as the first matching row is found. See
[EF Core documentation — Any / Count performance](https://learn.microsoft.com/ef/core/performance/efficient-querying#use-any-or-count)
and the .NET API reference for [`Queryable.Any`](https://learn.microsoft.com/dotnet/api/system.linq.queryable.any)
and [`Queryable.Count`](https://learn.microsoft.com/dotnet/api/system.linq.queryable.count).

## Bad

```csharp
if (db.Blogs.Count() > 0)
{
    // ...
}

bool hasBlogs = db.Blogs.Where(b => b.Id > 0).Count() != 0;
```

## Good

```csharp
if (db.Blogs.Any())
{
    // ...
}

bool hasBlogs = db.Blogs.Where(b => b.Id > 0).Any();
```

## Code fix

Replaces the whole comparison with `Any()` on the same query, preserving the surrounding query
chain and trivia. Fix All applies the change to every reported comparison in the document.

The rule is intentionally narrow: comparisons such as `== 0`, `< 1`, `> 1` or `>= 2` are not
reported because they do not map one-to-one to `Any()`.

## Configuration

```ini
dotnet_diagnostic.EFL1002.severity = error
eflint.EFL1002.enabled = false
```
