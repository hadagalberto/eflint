# EFL3002 — Interpolated SQL flattened to a string

**Category:** Security · **Severity:** Warning · **Code fix:** no

## What

An interpolated SQL string is assigned to a `string` local (or field-like local via `var`)
and that local is later passed to `FromSqlRaw`, `ExecuteSqlRaw`, `ExecuteSqlRawAsync` or
`SqlQueryRaw`. EfLint follows simple assignments within the containing method or lambda.

## Why

C# evaluates an interpolated string assigned to `string` immediately. EF Core only sees the
final text, so every interpolated value is embedded in the SQL instead of being bound as a
parameter. This is the same injection risk as EFL3001, hidden behind a local variable.

## Bad

```csharp
string sql = $"SELECT * FROM Posts WHERE Title = {search}";
var posts = context.Posts.FromSqlRaw(sql);
```

## Good

```csharp
var posts = context.Posts.FromSql($"SELECT * FROM Posts WHERE Title = {search}");
```

## Configuration

```ini
dotnet_diagnostic.EFL3002.severity = error
eflint.EFL3002.enabled = false
```
