# EFL1005 — First/FirstOrDefault without OrderBy

**Category:** Performance · **Severity:** Warning · **Code fix:** no

## What

EfLint reports a `First()` or `FirstOrDefault()` call on an EF Core query chain that has no
`OrderBy`, `OrderByDescending`, `ThenBy` or `ThenByDescending`. Without a deterministic ordering,
the row that is returned is whichever one the database happens to produce first.

## Why

SQL result order is undefined unless the query has an `ORDER BY` clause. The row picked by
`First`/`FirstOrDefault` can therefore change between calls, as data changes, or after a query plan
changes. Add an explicit, stable ordering before materializing a single row. See
[EF Core documentation — Ordering data](https://learn.microsoft.com/ef/core/querying/ordering) and
[LINQ orderby clause](https://learn.microsoft.com/dotnet/csharp/language-reference/keywords/orderby-clause).

## Bad

```csharp
var blog = db.Blogs.First();
var firstActive = db.Blogs.Where(b => b.Id > 0).FirstOrDefault();
```

## Good

```csharp
var blog = db.Blogs.OrderBy(b => b.Id).First();
var firstActive = db.Blogs
    .Where(b => b.Id > 0)
    .OrderBy(b => b.Name)
    .ThenBy(b => b.Id)
    .FirstOrDefault();
```

## Code fix

No automatic fix. Only you know which column (or combination of columns) makes the choice
deterministic for your business rule, so add the appropriate `OrderBy` (and `ThenBy` for ties)
yourself.

## Configuration

```ini
dotnet_diagnostic.EFL1005.severity = error
eflint.EFL1005.enabled = false
```
