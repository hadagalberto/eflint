# EFL1010 — Multiple collection Includes without AsSplitQuery

**Category:** Performance · **Severity:** Warning · **Code fix:** yes

## What

EfLint reports a query that includes two or more distinct **collection** navigations (for example
`Include(b => b.Posts).Include(b => b.Tags)`) when the query chain does not already call
`AsSplitQuery()` or `AsSingleQuery()`. Both the lambda and the string-path form of `Include` are
recognized. Reference navigations (such as `Include(b => b.Owner)`) do not count towards the
threshold. One diagnostic is reported on the last collection `Include` in the chain.

## Why

By default EF Core translates a query with multiple collection includes into a single SQL `JOIN`.
The product of the collection cardinalities is materialized, so a blog with 10 posts and 10 tags
produces 100 rows for that one blog — the classic cartesian explosion. Larger collections make the
result set grow dramatically and waste bandwidth and memory. `AsSplitQuery()` executes one SQL query
per include and combines the results in memory, which is usually much cheaper for this shape. See
[EF Core — Single vs. split queries](https://learn.microsoft.com/ef/core/querying/single-split-queries)
and [EF Core — Eager loading](https://learn.microsoft.com/ef/core/querying/related-data/eager).

## Bad

```csharp
var blogs = db.Blogs
    .Include(b => b.Posts)
    .Include(b => b.Tags)
    .ToList();

// String paths are diagnosed too.
var blogs = db.Blogs.Include("Posts").Include("Tags").ToList();
```

## Good

```csharp
var blogs = db.Blogs
    .Include(b => b.Posts)
    .Include(b => b.Tags)
    .AsSplitQuery()
    .ToList();

// Or opt back into the single-query shape explicitly when that is intentional.
var blogs = db.Blogs
    .Include(b => b.Posts)
    .Include(b => b.Tags)
    .AsSingleQuery()
    .ToList();
```

## Code fix

The code fix inserts `.AsSplitQuery()` after the last `Include` in the query chain, before any later
operators such as `Where` or `ToList`. Trivia and formatting are preserved.

## Configuration

```ini
dotnet_diagnostic.EFL1010.severity = error
eflint.EFL1010.enabled = false
```
