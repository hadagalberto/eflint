# EFL2002 — Async EF operation ignores an available CancellationToken

**Category:** Correctness · **Severity:** Warning · **Code fix:** yes

## What

EfLint reports EF Core asynchronous operations (`ToListAsync`, `CountAsync`, `FirstAsync`,
`SaveChangesAsync`, `FindAsync`, `ExecuteDeleteAsync`, …) called without a
`CancellationToken` argument while a token parameter or local is in scope. Locals declared
after the call are not considered; a token passed explicitly (including `CancellationToken.None`)
satisfies the rule.

## Why

Without a token the database work continues after the caller has cancelled — for example during
an ASP.NET request abort or application shutdown. Passing the token is the only way EF Core can
cancel the command and release the connection promptly. See
[EF Core documentation — Cancellation tokens](https://learn.microsoft.com/ef/core/querying/async#cancellation-tokens).

## Bad

```csharp
public async Task<List<Blog>> GetAsync(BlogContext db, CancellationToken ct)
{
    return await db.Blogs.ToListAsync();
}
```

## Good

```csharp
public async Task<List<Blog>> GetAsync(BlogContext db, CancellationToken ct)
{
    return await db.Blogs.ToListAsync(ct);
}
```

## Code fix

Adds the in-scope token as the last argument of the asynchronous call. Fix All inserts the token
into every reported call in the document.

## Configuration

```ini
dotnet_diagnostic.EFL2002.severity = error
eflint.EFL2002.enabled = false
```
