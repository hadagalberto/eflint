# EFL1003 — Read-only query without AsNoTracking

**Category:** Performance · **Severity:** Info · **Code fix:** yes

## What

EfLint reports an EF Core materializing call (`ToList`, `ToArray`, `First`,
`FirstOrDefault`, `Count`, `Any`, …) when the query is rooted in a
`DbContext`/`DbSet`, the query chain has no `AsNoTracking` (or
`AsNoTrackingWithIdentityResolution`, or an explicit `AsTracking` choice), and the
enclosing method never writes. A method is considered to write when it calls
`SaveChanges`/`SaveChangesAsync`, `Add`/`AddRange`, `Update`/`UpdateRange`,
`Remove`/`RemoveRange` or `Attach` on a context or `DbSet`, or assigns to a property
of a local variable. The analysis is intentionally conservative: when in doubt it
stays silent. LINQ-to-Objects calls are never reported.

## Why

By default EF Core tracks every entity it materializes: it keeps a reference in the
change tracker and takes a snapshot of property values so `SaveChanges` can detect
modifications. For a query whose results are only read, that work is pure overhead —
extra allocations, slower queries and a tracker that grows for the lifetime of the
scope. `AsNoTracking` skips attaching the entities to the context. See
[EF Core documentation — Tracking and no-tracking queries](https://learn.microsoft.com/ef/core/querying/tracking).

## Bad

```csharp
public List<Blog> GetAll(BlogContext db)
{
    return db.Blogs.Where(b => b.Id > 0).ToList();
}
```

## Good

```csharp
public List<Blog> GetAll(BlogContext db)
{
    return db.Blogs.Where(b => b.Id > 0).AsNoTracking().ToList();
}
```

No diagnostic is produced when the method also modifies data, because tracking is
then required:

```csharp
public Blog Rename(BlogContext db, string name)
{
    var blog = db.Blogs.First();
    blog.Name = name;
    db.SaveChanges();
    return blog;
}
```

## Code fix

Inserts `.AsNoTracking()` immediately before the materializing call, preserving the
rest of the chain and the document's formatting, e.g.
`db.Blogs.Where(...).ToList()` becomes `db.Blogs.Where(...).AsNoTracking().ToList()`.
If the query already configures tracking, no fix is offered. Fix All applies the
same change to every reported call in the document.

## Configuration

```ini
dotnet_diagnostic.EFL1003.severity = warning
eflint.EFL1003.enabled = false
```

The rule is informational by default and can be disabled entirely with
`eflint.EFL1003.enabled = false`.
