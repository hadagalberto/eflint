# EFL2005 — DbContext registered as a singleton

**Category:** Correctness · **Severity:** Warning · **Code fix:** no

## What

EfLint reports `services.AddSingleton<TContext>()` where `TContext` derives from `DbContext`,
and `AddDbContext<TContext>(..., ServiceLifetime.Singleton)`. The check is symbol-based, so
look-alike methods on unrelated types are ignored.

## Why

`DbContext` holds per-request state (the change tracker and loaded entities) and is not
thread-safe. A singleton instance is shared by every request, leaks tracked entities and causes
concurrent access. The default and correct lifetime is scoped. See
[EF Core documentation — DbContext lifetime, configuration, and initialization](https://learn.microsoft.com/ef/core/dbcontext-configuration/).

## Bad

```csharp
services.AddSingleton<BlogContext>();
services.AddDbContext<BlogContext>(options => { }, ServiceLifetime.Singleton);
```

## Good

```csharp
services.AddDbContext<BlogContext>(options => { }, ServiceLifetime.Scoped);
// or simply:
services.AddDbContext<BlogContext>(options => { });
```

## Configuration

```ini
dotnet_diagnostic.EFL2005.severity = error
eflint.EFL2005.enabled = false
```
