# EFL2007 — String comparison inside an EF query

**Category:** Correctness · **Severity:** Info · **Code fix:** no

## What

EfLint reports `string.Equals(a, b, StringComparison.X)` and comparisons using `ToLower()`,
`ToUpper()`, `ToLowerInvariant()` or `ToUpperInvariant()` inside EF query lambdas. The suggested
alternative depends on `eflint.provider`: `postgres` suggests `EF.Functions.ILike` or
`EF.Functions.Collate`, `sqlite` suggests `EF.Functions.Collate` with `NOCASE`, and other
providers suggest a case-insensitive collation.

## Why

`ToLower()` and `ToUpper()` prevent index use (non-sargable) and several providers cannot
translate them or the `StringComparison` overload at all. Provider-specific collation or
`ILIKE` expresses the intent in SQL. See
[EF Core documentation — Collations and case sensitivity](https://learn.microsoft.com/ef/core/miscellaneous/collations-and-case-sensitivity)
and [PostgreSQL provider — ILIKE](https://www.npgsql.org/efcore/mapping/full-text-search.html).

## Bad

```csharp
var blogs = db.Blogs.Where(b => b.Name.ToLower() == "alice").ToList();
var match = db.Blogs.Where(b => string.Equals(b.Name, "alice", StringComparison.OrdinalIgnoreCase));
```

## Good

```csharp
// PostgreSQL
var blogs = db.Blogs.Where(b => EF.Functions.ILike(b.Name, "alice")).ToList();

// Explicit collation
var match = db.Blogs.Where(b => EF.Functions.Collate(b.Name, "NOCASE") == "alice");
```

## Configuration

```ini
dotnet_diagnostic.EFL2007.severity = warning
eflint.EFL2007.enabled = false
eflint.provider = postgres
```
