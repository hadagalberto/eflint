# EFL1006 — Skip/Take without OrderBy

**Category:** Performance · **Severity:** Warning · **Code fix:** no

## What

EfLint reports `Skip` or `Take` on an EF Core query when no `OrderBy`, `OrderByDescending`,
`ThenBy` or `ThenByDescending` appears in the same query chain. In-memory LINQ
(`List<T>.Skip`, `db.Blogs.ToList().Skip(...)`) is not reported — the rule only follows queries
rooted in a `DbContext`/`DbSet`. Each unordered operator is reported separately, so a chain with
both `Skip` and `Take` produces two diagnostics.

## Why

SQL result sets have no guaranteed order unless an `ORDER BY` clause is supplied. Without an
explicit ordering the database may return rows in a different order between requests or query
plans, so a page can contain duplicates or skip rows entirely. See
[EF Core documentation — Pagination](https://learn.microsoft.com/ef/core/querying/pagination)
and [Ordering data](https://learn.microsoft.com/ef/core/querying/ordering).

## Bad

```csharp
var page = db.Blogs.Skip(pageIndex * pageSize).Take(pageSize).ToList();

var first = db.Blogs.Take(5).ToList();
```

## Good

```csharp
var page = db.Blogs
    .OrderBy(b => b.Id)
    .Skip(pageIndex * pageSize)
    .Take(pageSize)
    .ToList();

var first = db.Blogs.OrderByDescending(b => b.Id).Take(5).ToList();
```

Prefer a stable, unique key (for example the primary key) as the final ordering to keep pages
consistent across calls.

## Automatic fix

None. Choosing the correct ordering depends on the entity and the desired page semantics, so the
diagnostic is message-only.

## Configuration

```ini
dotnet_diagnostic.EFL1006.severity = error
eflint.EFL1006.enabled = false
```
