# EFL2004 — DbContext used across threads

**Category:** Correctness · **Severity:** Warning · **Code fix:** no

## What

EfLint reports a `DbContext` instance captured by a lambda passed to `Parallel.For`,
`Parallel.ForEach`, `Parallel.Invoke` or `Task.WhenAll`. Captured locals, parameters and fields
whose type derives from `DbContext` are recognized; a context created inside the lambda is fine.

## Why

`DbContext` is not thread-safe. Concurrent use of one instance corrupts its change tracker and
can produce `DbUpdateConcurrencyException`, invalid SQL or data loss. Create a separate context
per unit of work — for parallel work, use a scope/context per iteration. See
[EF Core documentation — Thread safety](https://learn.microsoft.com/ef/core/dbcontext-configuration/#avoiding-dbcontext-threading-issues)
and the [ASP.NET Core DbContext registration guidance](https://learn.microsoft.com/ef/core/dbcontext-configuration/).

## Bad

```csharp
Parallel.ForEach(ids, id =>
{
    var blog = db.Blogs.First(b => b.Id == id);
    blog.Name = "updated";
    db.SaveChanges();
});
```

## Good

```csharp
Parallel.ForEach(ids, id =>
{
    using var scoped = new BlogContext();
    var blog = scoped.Blogs.First(b => b.Id == id);
    blog.Name = "updated";
    scoped.SaveChanges();
});
```

## Configuration

```ini
dotnet_diagnostic.EFL2004.severity = error
eflint.EFL2004.enabled = false
```
