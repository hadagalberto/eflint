# EFL2008 — Redundant Update/Attach on a tracked entity

**Category:** Correctness · **Severity:** Warning · **Code fix:** no

## What

EfLint reports `Update` or `Attach` on an entity that was loaded earlier in the same method from
the same `DbContext` instance. The analysis follows the last value assigned to a local and
recognizes materializers such as `First`, `Single`, `ToList` and their async counterparts.
Entities from a different context or freshly constructed entities are not reported.

## Why

Query results are tracked automatically. Calling `Update` or `Attach` again marks every property
as modified, so `SaveChanges` issues an `UPDATE` for all columns even when nothing changed —
wasting I/O and overwriting concurrent edits. See
[EF Core documentation — Explicit tracking](https://learn.microsoft.com/ef/core/change-tracking/explicit-tracking)
and [Update and Attach methods](https://learn.microsoft.com/ef/core/saving/disconnected-entities).

## Bad

```csharp
var blog = db.Blogs.First(b => b.Id == id);
blog.Name = "new name";
db.Update(blog);
db.SaveChanges();
```

## Good

```csharp
var blog = db.Blogs.First(b => b.Id == id);
blog.Name = "new name";
await db.SaveChangesAsync(); // tracked entity; no Update needed
```

For entities coming from a different context (disconnected entities), use `Update` or `Attach`
and mark only the changed properties as modified.

## Configuration

```ini
dotnet_diagnostic.EFL2008.severity = error
eflint.EFL2008.enabled = false
```
