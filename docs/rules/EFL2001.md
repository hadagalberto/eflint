# EFL2001 — Synchronous EF operation inside an async method

**Category:** Correctness · **Severity:** Warning · **Code fix:** yes

## What

EfLint reports synchronous EF Core operations inside `async` methods when an asynchronous
overload exists: `ToList`, `ToArray`, `First`, `FirstOrDefault`, `Single`, `SingleOrDefault`,
`Last`, `LastOrDefault`, `Count`, `LongCount`, `Any`, `All`, `Sum`, `Min`, `Max`, `Average`,
`ElementAt`, `Contains`, `ExecuteDelete`, `ExecuteUpdate`, `SaveChanges` and `Find`.
The receiver must be an EF query rooted in a `DbContext`/`DbSet`; LINQ-to-Objects calls are
never reported.

## Why

A synchronous database call blocks the thread while the query waits for I/O. In ASP.NET this
consumes a thread-pool worker for the whole round-trip and can cause thread starvation under
load. EF Core provides `...Async` overloads for these operations. See
[EF Core documentation — Asynchronous queries](https://learn.microsoft.com/ef/core/querying/async).

## Bad

```csharp
public async Task<Blog> GetAsync(BlogContext db, int id, CancellationToken ct)
{
    var blogs = db.Blogs.ToList();
    var count = db.Blogs.Count();
    db.SaveChanges();
    return db.Find<Blog>(id);
}
```

## Good

```csharp
public async Task<Blog> GetAsync(BlogContext db, int id, CancellationToken ct)
{
    var blogs = await db.Blogs.ToListAsync(ct);
    var count = await db.Blogs.CountAsync(ct);
    await db.SaveChangesAsync(ct);
    return await db.FindAsync<Blog>(new object[] { id }, ct);
}
```

## Code fix

Replaces the method with its `Async` counterpart, adds `await`, and passes an in-scope
`CancellationToken` when one is available. `Find` is special-cased: its asynchronous overloads
take the key values as an explicit `object[]` and the token last. When no token is in scope the
fix adds only `await`. Fix All applies the same transformation to every reported call.

## Configuration

```ini
dotnet_diagnostic.EFL2001.severity = error
eflint.EFL2001.enabled = false
```
