# EFL2006 — Include ignored after a projection

**Category:** Correctness · **Severity:** Warning · **Code fix:** yes

## What

EfLint reports an `Include` call in an EF query chain that is later projected with `Select` or
`SelectMany`. EF Core discards the include when the result shape changes, so the related
entities are never loaded.

## Why

`Include` only affects queries that materialize entity instances. A projection to an anonymous
type, a scalar or another shape removes the navigation from the result, so the generated SQL does
not join the included table. See
[EF Core documentation — Loading related data](https://learn.microsoft.com/ef/core/querying/related-data/eager).

## Bad

```csharp
var ids = db.Blogs
    .Include(b => b.Posts)
    .Select(b => b.Id)
    .ToList();
```

## Good

```csharp
// Project the navigation explicitly:
var rows = db.Blogs
    .Select(b => new { b.Id, Posts = b.Posts.Select(p => p.Title).ToList() })
    .ToList();

// Or drop the projection and load the entities:
var blogs = db.Blogs.Include(b => b.Posts).ToList();
```

## Code fix

Removes the ignored `Include` call (or the first argument of the static form). Chains that
contain `ThenInclude` are reported but not auto-fixed, because removing only the root include
would leave a dangling `ThenInclude`. Fix All removes every safe include in the document.

## Configuration

```ini
dotnet_diagnostic.EFL2006.severity = error
eflint.EFL2006.enabled = false
```
